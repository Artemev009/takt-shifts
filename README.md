# Такт — управление сменами

Рабочий прототип гибкого графика и учёта выходов для одной точки. Руководитель задаёт требуемое число сотрудников на каждый час с 08:00 до 20:00. Сотрудник выбирает смену длительностью от пяти часов, руководитель подтверждает заявку, после чего сотрудник отмечает фактический приход и уход.

[Открытая демоверсия для презентации](https://artemev009.github.io/takt-shifts/) — примерные данные, вход не требуется. Действия в демоверсии остаются в браузере посетителя.

Рабочая версия с авторизацией: https://takt-shifts-2026.perospilsa.chatgpt.site

## Сценарий показа

1. Войдите с аккаунта руководителя, которому владелец сайта открыл доступ. Дата по умолчанию — текущий день по Москве.
2. Задайте потребность на несколько часов и посмотрите нехватку на графике.
3. С другого разрешённого аккаунта сотрудника отметьте доступность в «Моих заявках», затем выберите интервал от пяти часов и отправьте заявку.
4. В кабинете руководителя откройте блок «Требует внимания», подтвердите заявку и посмотрите, как изменилось плановое покрытие.
5. Руководитель выдаёт временный код точки на главном экране. На месте сотрудник вводит его при приходе и уходе. Если отметку пропустили, отправьте запрос с временем по Москве и причиной: руководитель подтвердит или отклонит его. Для итогов используйте таблицы дня и недели, затем скачайте CSV.

На входном экране есть кнопка «Войти в личный кабинет», после входа отображаются имя, адрес и роль пользователя. Доступ к самому сайту регулируется в Sites: сотрудников нужно добавить в список доступа перед подключением. После выхода пользователь видит экран входа ChatGPT — это ожидаемое поведение защиты сайта.

## Как устроено

- Интерфейс и API работают в одном Cloudflare Worker, данные сохраняются в D1. Миграции находятся в `drizzle/`.
- Роль руководителя определяется сервером по проверенному адресу авторизованного пользователя и переменной окружения `MANAGER_EMAIL`. Остальные допущенные пользователи получают роль сотрудника.
- До настройки руководителем потребность не задана; система не подставляет выдуманный план. Заявка на смену имеет состояния `pending`, `approved`, `rejected`; до подтверждения она не учитывается в покрытии.
- Доступность хранится отдельно от заявки по дате: «могу выйти» с интервалом или «не могу». Нельзя подать заявку вне объявленного интервала или объявить недоступность поверх уже существующей заявки. Руководитель видит статусы команды.
- Пропущенный приход или уход запрашивается сотрудником для подтверждённой смены, с причиной и предложенным временем по Москве. Руководитель рассматривает заявку; только после подтверждения обновляются фактические часы. Открытые смены прошлых дней и ожидающие решения собраны в «Требует внимания».
- На текущий день нельзя запросить или подтвердить интервал, начало которого уже прошло. Приход принимается в согласованный интервал. Для отметки нужен шестизначный код точки, который руководитель выдаёт на четыре часа. После пяти неверных попыток ввод блокируется на 15 минут. Код — проверка присутствия у руководителя на точке для пилота; его можно передать удалённо, поэтому это не бесспорное доказательство физического присутствия.
- Короткий выход сохраняет фактическое время и попадает в очередь руководителя. Он согласует или оспаривает причину; оспаривание не переписывает отметку. Решения по сменам, исправлениям и коротким выходам приходят в личные уведомления внутри сайта. Ключевые действия записываются в журнал руководителя.
- Один сотрудник может иметь одну заявку на дату. Время прихода и ухода записывает сервер. В кабинете руководителя есть недельная сетка смен по людям и дням. Интерфейс «Такт» содержит боковое меню, обзор, расписание, заявки, потребность, отчёты и личный кабинет. Данные в этих разделах поступают из серверного API. Завершённую смену нельзя переписать через повторную заявку.
- Сотрудник видит только собственную историю; имена других сотрудников в графике скрыты. Руководитель видит заявки, команду и недельные итоги.
- Интерфейс считает плановое покрытие по подтверждённым интервалам, а фактические часы — по отметкам времени. Это разные показатели.

## Проверка

Из корня проекта: `bash scripts/build.sh && node tests/workflow.mjs`. Нужен Node.js с поддержкой `node:sqlite`. Для развёртывания на другой площадке потребуются собственные D1, настройка авторизации и секрет `MANAGER_EMAIL` со списком адресов руководителей через запятую. Этот секрет и рабочие данные не входят в репозиторий.

Тест поднимает базу в памяти, применяет миграции и проверяет роли, доступность, заявки, согласование, код точки, разбор коротких смен, исправления времени, уведомления, приватность и недельные данные. Разметка и клиентский скрипт проходят базовую проверку. Проверка реального входа и отображения на устройствах зависит от доступных авторизованных аккаунтов и выполняется отдельно перед полноценным запуском.

## Границы версии

Это версия для одной точки и пилота. В ней нет начисления зарплаты, распределения по нескольким ресторанам и интеграции с кадровой системой. Владелец должен добавить адреса сотрудников в список доступа Sites. Уведомления видны после входа в приложение, без e-mail и push. Для использования на реальной смене нужно проверить вход на устройствах сотрудников и согласовать правила обработки опозданий и пропущенных отметок.
