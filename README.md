# Такт — управление сменами

Пилотное веб-приложение для управления гибкими сменами в одной организации. Руководитель задаёт почасовую потребность по отделам (в том числе для ночных смен); сотрудник выбирает интервал от пяти часов, руководитель согласует заявку, после чего фиксируются фактические приход и уход.

**[Открыть рабочее веб-приложение «Такт»](https://takt-shifts-live.perospilsa.workers.dev/)** — отдельный HTTPS-сайт на Cloudflare Worker с D1 и входом по паролю. Подтверждена проверка `/healthz`, страницы входа, PWA и отказа анонимному API (27 октября 2026 года). Для первого входа используйте логин и пароль руководителя, заданные в GitHub Actions Secrets при начальном развёртывании.

[Открытая демоверсия для презентации](https://artemev009.github.io/takt-shifts/) — примерные данные, вход не требуется. Действия в демоверсии остаются в браузере посетителя.

Версия с серверной авторизацией через ChatGPT Sites (может требовать доступ к ChatGPT): https://takt-shifts-2026.perospilsa.chatgpt.site

Рабочая версия опубликована без зависимости от ChatGPT. Инструкция по дальнейшим обновлениям: [docs/STANDALONE-WEBAPP.md](docs/STANDALONE-WEBAPP.md).

## Сценарий показа

1. Войдите с аккаунта руководителя, которому владелец сайта открыл доступ. Дата по умолчанию — текущий день по Москве.
2. Задайте потребность на несколько часов и посмотрите нехватку на графике.
3. С другого разрешённого аккаунта сотрудника отметьте доступность в «Моих заявках», затем выберите интервал от пяти часов и отправьте заявку.
4. В кабинете руководителя откройте блок «Требует внимания», подтвердите заявку и посмотрите, как изменилось плановое покрытие.
5. Руководитель выдаёт временный код точки на главном экране. На месте сотрудник вводит его при приходе и уходе. Если отметку пропустили, отправьте запрос с временем по Москве и причиной: руководитель подтвердит или отклонит его. Для итогов используйте таблицы дня и недели, затем скачайте CSV.

Для самостоятельного Cloudflare-сайта руководитель создаёт сотрудникам отдельные логины и временные пароли в разделе «Команда и доступ». На входе и после выхода ChatGPT не требуется. Доступ через ChatGPT Sites относится только к старой альтернативной версии.

## Самостоятельное веб-приложение без ChatGPT

Для настоящего использования сотрудниками используйте **отдельную HTTPS-публикацию Cloudflare Worker и D1**, а не демонстрационный GitHub Pages и не входной шлюз ChatGPT Sites. В проект добавлены изолированная публикация, привязка к **явному ID базы**, создание первого руководителя и автоматическая проверка конфигурации. Инструкция: [docs/STANDALONE-WEBAPP.md](docs/STANDALONE-WEBAPP.md).

Рабочий Worker опубликован по адресу **https://takt-shifts-live.perospilsa.workers.dev/**. Cloudflare-аккаунт, D1 и GitHub Actions Secrets уже были использованы для успешного выпуска. Последующие обновления запускаются вручную через `Deploy standalone Takt web app` с `bootstrap_manager=false`. После первого входа смените временный пароль руководителя и удалите секрет `TAKT_MANAGER_PASSWORD` из GitHub Actions.

## Как устроено

- Интерфейс и API работают в одном Cloudflare Worker, данные сохраняются в D1. Миграции находятся в `drizzle/`.
- Сайт устанавливается на iPhone и Android как PWA: после добавления на домашний экран он открывается отдельной иконкой без адресной строки. Service worker не кеширует персональные данные и API-ответы.
- В самостоятельной версии роли хранятся на сервере в D1: руководитель создаёт аккаунты сотрудников с паролями, а доступ определяется серверной сессией. Для старой версии ChatGPT Sites отдельно поддерживается `MANAGER_EMAIL`.
- До настройки руководителем потребность не задана; система не подставляет выдуманный план. Заявка на смену имеет состояния `pending`, `approved`, `rejected`; до подтверждения она не учитывается в покрытии.
- Доступность хранится отдельно от заявки по дате: «могу выйти» с интервалом или «не могу». Нельзя подать заявку вне объявленного интервала или объявить недоступность поверх уже существующей заявки. Руководитель видит статусы команды.
- Пропущенный приход или уход запрашивается сотрудником для подтверждённой смены, с причиной и предложенным временем по Москве. Руководитель рассматривает заявку; только после подтверждения обновляются фактические часы. Открытые смены прошлых дней и ожидающие решения собраны в «Требует внимания».
- На текущий день нельзя запросить или подтвердить интервал, начало которого уже прошло. Приход принимается в согласованный интервал. Для отметки нужен шестизначный код точки, который руководитель выдаёт на четыре часа. После пяти неверных попыток ввод блокируется на 15 минут. Код — проверка присутствия у руководителя на точке для пилота; его можно передать удалённо, поэтому это не бесспорное доказательство физического присутствия.
- Короткий выход сохраняет фактическое время и попадает в очередь руководителя. Он согласует или оспаривает причину; оспаривание не переписывает отметку. Решения по сменам, исправлениям и коротким выходам приходят в личные уведомления внутри сайта. Ключевые действия записываются в журнал руководителя.
- Один сотрудник может иметь одну заявку на дату. Время прихода и ухода записывает сервер. В кабинете руководителя есть недельная сетка смен по людям и дням. Интерфейс «Такт» содержит боковое меню, обзор, расписание, заявки, потребность, отчёты и личный кабинет. Данные в этих разделах поступают из серверного API. Завершённую смену нельзя переписать через повторную заявку.
- Созданный руководителем временный пароль требуется заменить при первом входе. Пароли хранятся только как индивидуально посоленные PBKDF2-хеши, а отключение сотрудника немедленно отзывает его серверные сессии.
- Сотрудник видит только собственную историю; имена других сотрудников в графике скрыты. Руководитель видит заявки, команду и недельные итоги.
- Интерфейс считает плановое покрытие по подтверждённым интервалам, а фактические часы — по отметкам времени. Это разные показатели.

## Проверка

Из корня проекта: `bash scripts/build.sh && node tests/workflow.mjs && node tests/deployment.mjs && node tests/public-smoke.mjs`. Нужен Node.js с поддержкой `node:sqlite`. Самостоятельное развёртывание на другом аккаунте Cloudflare потребует отдельной базы D1, GitHub Actions Secrets и нового руководителя. Рабочие пароли в репозиторий не входят.

Тест поднимает базу в памяти, применяет миграции и проверяет роли, доступность, заявки, согласование, код точки, разбор коротких смен, исправления времени, уведомления, приватность и недельные данные. Разметка и клиентский скрипт проходят базовую проверку. Проверка реального входа и отображения на устройствах зависит от доступных авторизованных аккаунтов и выполняется отдельно перед полноценным запуском.

## Границы версии

Это версия для одной организации и пилота. В ней нет начисления зарплаты, распределения по нескольким независимым организациям и интеграции с кадровой системой. Для самостоятельной версии руководитель создаёт аккаунты сотрудников в приложении — добавлять их в ChatGPT Sites не нужно. Уведомления доступны внутри личного кабинета, без e-mail и push. Перед использованием на реальных сменах необходимо проверить сквозной сценарий на двух устройствах, организовать резервное копирование D1 и согласовать правила учёта рабочего времени и персональных данных.
